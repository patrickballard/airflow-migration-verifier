What the audit checks

Every DAG, every template field, run by run

  • Each DAG file imported on Airflow 3, before and after the migration.
  • Every template field rendered on Airflow 2 and on Airflow 3 for the same fire times, so a shifted ds, logical_date or partition path shows up as a diff.
  • Context keys and template variables Airflow 3 removed (execution_date, next_ds, prev_ds and others) that your code still reads.
  • Operator arguments Airflow 3 rejects at parse time, such as mysql_conn_id= left behind when ruff swaps in SQLExecuteQueryOperator.
  • Cron and timedelta schedules whose run dates will shift, with the one-line pin that keeps your Airflow 2 dates.
